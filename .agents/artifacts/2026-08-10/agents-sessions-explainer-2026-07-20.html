01The memory model

There is no cross-agent RAM. Transcripts live where each agent writes them. The CLI indexes those paths and answers questions.

What “memory” actually means When an agent “recalls prior work,” it runs something like agents sessions "auth middleware" --since 7d (or reads a session id as markdown). That is search + read, the same way you’d grep logs — not a joint embedding store, not a hive mind.

02How devices connect

Three layers. Default is live SSH fan-out. Nothing requires R2.

ModeWhat it doesWhen
--localScan only this machine’s transcript rootsSpeed · scripting · JSON
--host / --deviceRun the query on remote(s) over SSH“What did zion do this week?”
default listingAuto fan-out to online fleet, host columnInteractive browse
import --from-hostCopy remote transcripts into a local mirror (tagged by origin machine)Offline recall later
sessions syncR2 CRDT merge across machines — opt-in beta, off by defaultAlways-on multi-machine archive
On this fleet right now agents sessions sync --status → automatic sync disabled, R2 credentials missing. Cross-machine recall uses live --host / fan-out, not a shared cloud brain.

05Cookbook for the question “do agents share memory?”

# No. But any agent can:
# 1) find related past work (any machine you can SSH to)
agents sessions --all --since 14d "fleet visibility" --host zion --host yosemite-s0 --flat

# 2) open the actual transcript slice
agents sessions <id> --markdown --last 10 --include user,assistant

# 3) see what's running fleet-wide right now
agents sessions --active

# 4) (optional) copy a peer's week into a local mirror
agents sessions import --from-host zion --since 7d
