Purpose

Two bugs filed as issue #2058:

Bug 1 — agents view side-effects. view <agent> ran a resource-drift scan at exit, detected unsynced user-repo resources, and incurred the scan overhead; if new resources were found it could present an interactive sync prompt. view is a read command; the side-effect mutated version-home state when confirmed and was unexpected in read-only contexts.

Bug 2 — agents doctor qualifier resolution. parseTargetArg (private) handled only two cases before falling through: a bare agent (no qualifier) via listInstalledVersions, and @default via a one-off getGlobalDefault branch. Exact semver versions worked via parseAgentSpec + isVersionInstalled. Symbolic qualifiers @latest, @oldest, @pinned, and @all were not handled — they passed through parseAgentSpec (which accepted them as parseable specs) but then failed isVersionInstalled because "latest" / "oldest" / "pinned" / "all" are not real installed version strings, producing "Claude@latest is not installed" errors. The shared resolveAgentTargets engine used by every other command was never called.
