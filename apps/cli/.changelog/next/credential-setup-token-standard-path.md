- **Zero Touch ID, no more daily logout: Claude auth now runs off a file-backed setup-token on the standard path.** agents-cli no longer reads or copies Claude Code's interactive/rotating login credential — the two things that caused the Touch ID storm and the fleet-wide daily logout. (1) `agents view` and balanced rotation drew usage bars by reading the login **keychain** (`loadClaudeOauth` → `getKeychainToken`), which pops a Touch ID authorization sheet because the item is ACL-bound to Claude Code, not us; usage + the auth-health probe now read the account's file-backed `claude setup-token` instead (`readAccountSetupToken`, no keychain, no prompt). (2) `agents apply` copied `.claude/.credentials.json` across machines (`login: sync`, the default) — copying a single-use rotating OAuth token invalidates it on the source, logging every other box out; `apply` now never captures or pushes a setup-token harness's login (claude), because its auth travels as the synced file-based auth bundle. (3) `buildExecEnv` injects the account's setup-token as `CLAUDE_CODE_OAUTH_TOKEN` on the **standard run path** — identical for interactive `agents run` and daemon/routine runs — so the daemon holds and injects no token of its own (the RUSH-1759 ambient-injection and RUSH-1979 drop-dance band-aids are deleted), and Claude Code authenticates from the env var without ever opening the keychain. A new registry (`CREDENTIAL_MODEL` in `apps/cli/src/lib/credentials.ts`) declares each harness's credential model (setup-token / api-key / login-only) so the never-copy rule is registry-driven, not hardcoded per agent. Seed or refresh a setup-token yourself with `/fleet:mint-auth` (drives the OAuth flow via a pty + a logged-in browser).
