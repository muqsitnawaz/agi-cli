- **Cursor multi-account support via named API-key accounts; browser OAuth isolation claim corrected (RUSH-2400, RUSH-2402).** Cursor's browser OAuth is device-global — one sign-in per machine, shared across all installed versions. A prior CHANGELOG entry (1.22.34) incorrectly described per-version XDG isolation as the multi-account mechanism; `buildExecEnv` never actually isolated Cursor's OAuth token per version home, so the account you selected was discarded at exec. That XDG branch is removed (`lib/exec.ts`), the shim no longer exports `XDG_CONFIG_HOME` for Cursor (`lib/shims.ts`, `CONFIG_ENV_ISOLATED_AGENTS`), and the migration that seeded OAuth tokens into per-version homes is gone (`lib/migrate.ts`). Multiple Cursor accounts are now real through **named API-key accounts**: `agents accounts add <name> --provider cursor --auth api-key --from-secrets <bundle>:<KEY>` registers one, `agents accounts set-key <name>` rotates it, and `agents accounts inspect <name>` verifies it. `agents run cursor --account <name>` injects `CURSOR_API_KEY` into the child process — overriding any profile or ambient value — and fails closed when the account is missing. Bare `agents run cursor` (balanced rotation) includes healthy named API-key accounts as candidates targeting the newest installed version, so rotation works without an explicit `--account` flag. Usage is unavailable for API-key accounts (`usageApiKeyUnverifiableError`): Cursor exposes no per-API-key usage endpoint, so `agents view cursor` shows a `usage unavailable` notice rather than misattributing the device OAuth session to the API-key account.
