- **`agents sessions preview <short-id>` no longer refuses to render when an unrelated device is offline (RUSH-2479 follow-up).** Short-ID resolution was modeled as a fleet-wide uniqueness consensus: `metadataResolveOutcome` returned `partial` — nothing rendered, exit 2 — the moment any registered device was unreachable, even when this machine's index already held the unique match, and `--local` was the workaround. Resolution now keys on the **owner device** (`session.machine`), not on whether every registered peer answered: a short ID unique across the *reachable* fleet resolves to a new `resolved-unconfirmed` outcome carrying the offline peers. A READ path (`sessions preview`, `--resolve`) renders the match and names the offline device; an ACT path (`resume`, `attach`, `focus`, `exec --resume`) still fails closed on an unconfirmed prefix, because a dark peer can hold a distinct session sharing the 8-hex prefix (`fleetCandidatesByQuery` groups by full id, so that collision is invisible) and resuming the wrong conversation is unrecoverable — pass the full UUID to resume regardless. A full UUID resolves exactly as before (globally unique, zero-SSH local hit preserved); a **label** stays fail-closed (labels genuinely collide across boxes); `partial` is now reserved for the one undecidable case — no reachable device holds the match while a peer is offline. `--local` is now an optimization, not a requirement, for a peek. Contract: `SES-9a`.
