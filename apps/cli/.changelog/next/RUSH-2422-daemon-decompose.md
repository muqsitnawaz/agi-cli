- **Daemon internals: `runDaemon()` decomposed and the shadowed `getDaemonDir` untangled (RUSH-2422, RUSH-2423).** Refactor with no behaviour change, except two user-visible ones noted below. RUSH-2353 moved the cron-shaped ticks out of the 490-line `runDaemon()` into `daemon-ticks.ts` but left four background ticks inline (self-heal, secrets-broker self-heal, keychain reap, state-dir self-check); their bodies now live in `daemon-ticks.ts` too, taking their dependencies explicitly, with `runDaemon` keeping only the wiring — cadence, re-entrancy, and the shutdown hook. The four hand-rolled in-flight booleans collapse into one `onceAtATime` helper. `getDaemonDir` was defined twice with different behaviour — `state.ts`'s resolves the path, `daemon.ts`'s also created the directory — which forced `daemon.ts` to alias its own import to dodge the collision; the local one is now `ensureDaemonDir`, named for the side effect that is the whole difference. The daemon's log path is exported as `getDaemonLogPath()` and the two commands that rebuilt it from a hardcoded `'logs.jsonl'` literal now call it, so renaming the file cannot silently point them at nothing. Timing constants that were inline literals are named beside the existing ones. **User-visible:** `handleShutdown` is now structurally single-shot, so repeated SIGTERMs during shutdown run it once instead of relying on every step inside it happening to be idempotent. Source: `apps/cli/src/lib/daemon.ts`, `apps/cli/src/lib/daemon-ticks.ts`, `apps/cli/src/commands/daemon.ts`, `apps/cli/src/commands/routines.ts`.
