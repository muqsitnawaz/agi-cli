- **Rush Cloud no longer reads the interactive Claude login when building account credentials — it now reads only the file-based `agents secrets` setup-token (RUSH-2359 / incident #1767).** `readClaudeCredentialsBlob` in `src/lib/cloud/rush.ts` previously called `loadClaudeOauth(home)` without options on macOS (which reads the interactive Keychain login) and read `.credentials.json` directly on Linux — both are rotating OAuth tokens the Rush server must not hold. In the #1767 incident the interactive `claude setup-token` TTY stream (ANSI codes + banner) was captured as the raw credential blob, which then reached the `Authorization` header of every webhook-dispatched Rush Cloud run, crashing each job on startup and minting a live 1-year Anthropic token per run. The fix passes `{ accessTokenCache: true }` to `loadClaudeOauth`, which reads ONLY from the file-based `auth` bundle (`agents secrets` / `resolveClaudeSetupToken`) and never touches the Keychain or `.credentials.json`. A `isValidClaudeSetupToken` shape check (`/^sk-ant-oat01-[A-Za-z0-9_-]+$/`) is added as a second line of defence so any non-setup-token payload — rotating OAuth blob, TTY/ANSI banner, partial output — is rejected before it can reach the server. Source: `apps/cli/src/lib/cloud/rush.ts`.
