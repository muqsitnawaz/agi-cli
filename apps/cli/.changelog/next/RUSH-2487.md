- **A project definition can bind several local directories, each with its own GitHub remote, and every spawn path grants them (RUSH-2487).** `agents projects add <name> --dir <path...>` and `agents projects set <name> --add-dir <path...>` / `--rm-dir <path...>` bind (and unbind) additional local repo directories in `repos[]`. Each `--dir`/`--add-dir` names a **local directory**; its `owner/repo` slug is read by running `git remote get-url origin` **inside that directory** and normalizing it — never inferred from the directory path, because the checkout dir and its GitHub owner routinely differ (`~/src/github.com/muqsitnawaz/agents-cli` vs the `phnx-labs/agents-cli` remote). A directory with no `origin` takes an explicit `--slug owner/repo`, else the command errors; paths are stored home-relative. One resolver, `projectDirsAbs(def, { forRemote })` (`apps/cli/src/lib/projects.ts`), is the single source of a project's ordered directory list (primary `defaultPath ?? root` first, then each `repos[].path` joined with `repos[].subpath`, deduped; local drops non-existent dirs, remote keeps every home-relative entry), and the workspace probe (`workspaceTargetsForDef`) plus `agents run --project` and `agents teams create --project` all read it. At spawn the bound directories are folded into the harness's directory grants — Claude via native `--add-dir` (`apps/cli/src/lib/exec.ts:1269`) and Codex into its edit profile's `workspace_roots` (`apps/cli/src/lib/exec.ts:1133`); harnesses with no such surface drop the grants and run with the cwd only. The Factory / VS Codium extension reads the same resolver so an opened project binds the same set. Source: `apps/cli/src/lib/projects.ts`, `apps/cli/src/lib/project-probe.ts`, `apps/cli/src/commands/projects.ts`, `apps/cli/docs/11-projects.md`.
